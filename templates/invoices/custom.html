{# Renderer for a template built in the invoice template designer. Walks the validated placement spec (see invoice_spec.py) and emits the same parts every built-in layout uses. There is deliberately no branch here that can render arbitrary markup: an element type this file does not recognise produces nothing, and every string goes through Jinja autoescaping. invoice_spec.validate() guarantees the spec holds exactly one `fbr` element and one `items` element, both on the page, so a custom template cannot be saved without its FBR compliance marks. How free placement survives a long invoice ------------------------------------------ The designer lets a user put an element anywhere, which is fine for a masthead and fatal for the items table: a table pinned to a fixed box clips at forty lines, and absolutely positioned content does not paginate in WeasyPrint -- it just overflows off the paper. So the sheet is emitted as three bands in *normal* flow: 1. `.band-head` everything whose top edge is above the table. Fixed height, children absolutely placed inside it, so the designed arrangement is exact. 2. `.band-items` the table itself, in flow, with `min-height` set to the height it was given in the designer. Short invoices therefore keep the designed gap below the table; long ones grow and break across pages naturally. 3. `.band-tail` everything whose top edge is at or below the table's bottom. Fixed height, children absolutely placed relative to the table's bottom edge -- so totals and the FBR marks keep their designed relationship to each other and follow the table down however far it grew. `footer` is the exception: it leaves the bands and prints as a running footer at the bottom of every page, which is what a footer means on a multi-page invoice. Coordinates are millimetres on invoice_spec's 186x273mm canvas. The active density picks the real page margins, so `sx`/`sy` below rescale the canvas onto whatever printable area the theme actually has.
